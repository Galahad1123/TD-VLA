# TD-VLA 项目路线图

状态：P1 环境已验收，六任务 300 条 v4 数据已入选并建立 270/30 划分；P4 模型与诊断训练链路已通过运行验收。正式预训练初始化及闭环评测尚未完成。

## 1. 项目目标与当前边界

第一版研究基于 TurboVLA 的并行多流解码：共享 decoder 同时处理 Action、Track、Stage queries，在保持连续 action chunk 并行预测的前提下，验证跨流隐藏特征交互的价值。

已确认的约定：

- 输入当前多视角图像、任务指令和机器人状态；不增加 Temporal 历史、摘要模块或跨窗口模型缓存。
- Track 预测主视角中左右夹爪两指中点的未来目标轨迹；Stage 预测已知任务内当前阶段 ID。
- 仅使用选定 RoboTwin 任务的 Clean 数据训练，在 Clean 设置评测。
- 冻结 BERT；视觉、融合、decoder 和输出头等其余模块从开始联合训练，不采用先冻后解的分阶段训练。
- 第一版默认全流输出；第二版再研究自然按需生成。
- 本机开发，远端 `F43-6000x2` 的双卡 RTX PRO 6000 Blackwell Max-Q 负责主要数据生成、训练与评测，通过 [主仓库](https://github.com/Galahad1123/TD-VLA) 同步代码。
- 模型下载优先 hf-mirror.com，环境依赖优先清华源；具体版本、校验与回退遵循工程规范。

初始化的执行默认：使用基础视觉/语言预训练权重与官方 GroundingDINO 融合初始化，不使用已经在 RoboTwin Clean + Randomized 上训练过的成品策略初始化正式对照。官方策略只用于接口校验与外部参考，避免破坏 Clean-only 训练边界。

配套文档：

- [第一版模型架构](model-architecture-v1.md)：模型结构与注意力。
- [研究设计](research-design.md)：输出语义、研究假设及历史讨论。
- [工程约定](engineering-conventions.md)：目录、环境、实验产物及复现。

本路线图记录最新实验范围与冻结策略；旧文档中的早期候选不自动成为执行要求。各阶段开工前补充该阶段的具体实现清单，不提前为尚未校验的数据和环境锁死全部接口。

## 5. P2：任务子集与标注试验

### 5.1 候选任务

下表已获讨论认可，但锁定前须通过运行与标注验收。阶段描述只是候选，不是已完成的标注规则。

| 任务 | 覆盖能力 | 候选阶段结构 | 注意事项 |
| --- | --- | --- | --- |
| move_stapler_pad | 单臂抓放、左右手随位置选择 | 接近抓取、提起搬运、对齐放置、完成 | 物体朝向也是官方成功条件的一部分 |
| beat_block_hammer | 工具操作与目标接触 | 抓锤、提起移动、对准接触、完成 | 成功依据包含实际接触，不能只看二维距离 |
| lift_pot | 双臂同步抓持与抬升 | 接近、双侧抓持、协同抬升、完成 | 抓持距离、高度与姿态共同检查 |
| handover_block | 双臂交接与搬运 | 抓取提起、交接区、换手、搬运放置、完成 | 区分双手同时抓持与完成换手 |
| stack_blocks_two | 多对象顺序与堆叠 | 第一块抓放、第二块抓取、堆叠、释放完成 | 不保证每次都双臂，需识别物体身份 |
| place_object_basket | 放入物体后换臂提篮 | 抓物、入篮、抓篮、提篮、完成 | 专家脚本有恢复分支，规则不能依赖固定指令序号 |

先在 move_stapler_pad、lift_pot、handover_block 各检查少量成功专家回放，再覆盖其余三个任务。候选排除项 put_object_cabinet 的成功函数依赖专家流程设置字段，暂不纳入以减少接口风险；这不是已确认该任务不可用。

## 8. P5：双卡 Recipe 试验

目标是在开发/验证数据上选定适合双卡资源的训练配方，不照搬官方八卡规模。

- [ ] 先测数据读取、生成速度、训练吞吐、峰值显存和闭环评测耗时，估算单次及三组总成本。
- [ ] 全局 batch 128、学习率 5e-5 作为先导候选，非最终承诺；根据实测选择每卡 batch 和累积次数。
- [ ] 借鉴 AdamW、EMA、梯度裁剪和 warm-up 后常数学习率；确定具体值并记录修改依据。
- [ ] 用基线收敛曲线和开发评测选择训练预算；不照搬 150k 步，不把训练损失持续下降等同于泛化改善。
- [ ] 在有限、事先记录的范围内检查辅助损失量级，避免 Track/Stage 主导共享网络；两种多流模型共用配方。
- [ ] 固定检查点评选准则、评测频率、训练种子及中止条件，区分调参运行与正式运行。

产物：锁定的 recipe、吞吐与存储估算、先导实验记录、正式实验矩阵。

验收：训练稳定、无明显数据或梯度错误；能够解释预算选择；正式三组使用一致的有效 batch、更新预算、共有模块初始化和冻结策略。多流两组除 mask 外相同；原版缺少辅助输出是预期差异。启动正式实验前锁定训练步数、损失权重和种子数。

## 11. P8：第二版自然按需生成

在第一版结果明确后，将 mask 改为 Action 仅读自身、Track 读取 Action/Track、Stage 读取 Action/Stage。按新结构训练或微调，不能假定第一版改 mask 后性能保持。

- [ ] 支持 A、A+P、A+S、A+P+S 四种组合，实际移除未选辅助 query。
- [ ] 保持剩余 query 的身份与位置稳定，验证动作计算不依赖辅助流。
- [ ] 分别测量四种组合的控制、辅助指标及真实延迟，不以隐藏输出作为计算节省。
- [ ] 与第一版全双向结构比较交互收益和选择性推理代价。

后续可选方向：Temporal 历史、实际运动预测与次优数据、更多任务/Randomized 设置、其他 benchmark。它们需要独立协议，不自动扩大第一版范围。

## 12. 风险与对应决策

| 风险 | 处理阶段与方式 |
| --- | --- |
| 原始数据不足以补标 | P2 核验；必要时重新生成并记录来源变化 |
| 单时刻无法区分细阶段 | P2/P3 合并合理阶段或标记歧义；历史留后续 |
| 恢复分支破坏固定阶段序列 | P2 按状态定义阶段，不按脚本计数 |
| Clean 子集过拟合 | P3 独立轨迹划分；P5 依验证收敛确定预算 |
| 辅助流损害控制 | P5 检查损失与梯度；P6 与独立 mask 公平对照 |
| 双卡吞吐不足或数据瓶颈 | P5 实测后调整 batch/累积和读取，不先承诺步数 |
| 更改初始化混入 Randomized 经验 | P3/P5 锁定基础初始化来源，成品策略仅参考 |
| 仿真或恢复配置不可复现 | P1/P4 锁定版本、验证通信及恢复，P7 干净环境检查 |

# TD-VLA：Track 与任务阶段标注约定

更新日期：2026-11-14。状态：v4 已实现，并对现有六任务 12 条成功专家回合完成重标注。运行结果见 [v4 验收报告](../setup/p2-annotation-v4-validation.md)。

本文替代旧 P2 v3 候选规则。旧版派生标签、重跑副本与检查图已清理，原始专家数据保留。
`scripts/annotate_pilot.py` 现生成 `pilot-labels-v4`；旧逐帧分类函数仅保留用于历史回归测试，新入口不调用它们。不得把旧版输出改名冒充新版数据。

## 1. 目的与适用范围

Track 与 Stage 是与并行 Action chunk 同步输出的辅助模态，分别提供目标运动与任务进度监督。
不要求逐帧物理状态达到 100% 精确；重点是语义合理、时间对应清晰、生成方式简单且可复现。
第一版使用已知多任务的成功 Clean 专家回合。失败专家回合保留原始记录，不混入当前目标轨迹监督。
真实掉落、重抓与恢复分支的阶段表达留待后续扩展，不为其预先增加第一版复杂度。

## 2. Track：双臂完整目标轨迹

### 几何与坐标

沿用现有两指中点：左右夹爪各取两个固定指腹几何点，转换到世界坐标后取平均。
保持左右臂身份和几何来源可追溯即可，不要求与官方 TCP 一致，也不继续以精确接触中心为验收目标。
来源为成功专家执行过程中实际记录的几何位置，作为希望实现的目标运动参考；不是预测学习策略执行后实际发生的运动。

在每个控制窗口，以当前主摄像头内外参投影所选未来时刻的世界坐标，保存原图归一化坐标 `(u/W, v/H)`。
每个窗口为 `K × 2 × 2`：采样点、左右臂、二维坐标。模型读取新观测时同步更新 Action、Track 和 Stage。
图像 resize/crop 等预处理必须明确与该坐标约定的对应关系；原图坐标和处理后图像坐标不能混用。

### 遮挡、出画与闲置臂

- 遮挡和出画都保留真实投影并参与监督。归一化坐标可以小于 0 或大于 1，不裁剪，不用 sigmoid 限制输出范围。
- 闲置臂继续输出其静止或缓慢移动的轨迹，不增加活动臂选择器，不按任务丢弃一侧。
- 第一版左右臂同等监督，损失按有效点归一化；评估区分运动与静止窗口，防止静止轨迹掩盖操作臂误差。
- `in_frame`、遮挡提示可用于调试，但不作为训练有效性门槛，不要求生成逐点可见性真值。
- 仅时间越界填充、非有限投影、相机后方或近相机平面等无法正常投影的情况排除损失。近相机平面的数值阈值在实现中显式配置并记录。
- 不把被排除的点当成有效零坐标；掩码在损失计算前生效，防止非有限值污染训练。

### 覆盖时长与稀疏采样

Track 覆盖时长 `T`、采样点数 `K`、各点时间偏移独立于 Action chunk 的长度。
无需每个物理步计算或监督 Track，也不要求与每个 Action 采样点一一对应。
初始实验建议为未来 3 秒、10 个点，偏移为 0.3、0.6、…、3.0 秒；这是可调整的起始建议，不是已验证的最优配置。

当前原始数据约每 60 ms 记录一帧，末尾显式终止帧可能不等间隔；应根据实际时间戳选取未来点。
后续实现须记录目标时间偏移及实际取样时间，明确选帧或插值方法，不能用不均匀帧索引冒充精确固定时间。
原始中点与相机参数可按采样时刻保存，窗口按需组装，避免为重叠窗口重复存储大量密集标签。
超出回合终点的请求即使重复终止值填充，也必须排除对应损失；时间有效性与投影有效性分开记录。

## 3. Stage：Oracle 转换事件与区间赋值

### 标注流程

1. 先确认每个任务的操作流程与阶段序列，ID 为任务内编号，不跨任务强行共享语义。
2. 在完整成功 episode 中，利用仿真 Oracle 的物体位姿、接触、夹爪状态、支撑关系及官方成功信号，定位关键转换事件。
3. 可使用事件后的短时间证据确认事件成立，再把边界定位回该事件开始的帧；不得提前到事件尚未发生的时刻。
4. 得到有序边界 `b1 < b2 < …` 后，以左闭右开区间赋值：`[0,b1)` 为阶段 0，`[b1,b2)` 为阶段 1，依此类推；末段包含终止帧。
5. 边界确认后，段内短暂接触抖动不改变阶段，不因单帧接触缺失大面积屏蔽监督。

离线使用后续证据只服务于标签确认，Oracle 和未来观测不进入模型当前输入。
不按回合时间比例划阶段，不直接拿专家函数编号作为最终标签。
第一版成功专家轨迹采用任务流程顺序；必要事件缺失、顺序冲突或无法形成合理区间的回合列为待检查，禁止用时间比例强行补齐。
已有原始 Action 数据独立保留，Stage 无法确认不应破坏原始轨迹。

### 标签与共享分类头的对应约定

第一版使用一个共享 5 类 Stage 分类头，各任务仍保留下面的任务内阶段编号，不改为跨任务通用技能标签。训练在有效标签上使用 5 类交叉熵，不按任务屏蔽类别；推理先取原始最大 logit 的类别，再按该任务阶段数截断：`stage = min(raw_stage, C_task-1)`。例如 `lift_pot` 有 3 个阶段，从 0 开始的原始预测 2、3、4 均解码为阶段 2（完成）。

截断仅用于预测解码，不修改标注数据，不把无效标签 `-1` 截断成有效类别。评测同时保留截断后的准确率和原始越界率，防止越界预测被完成阶段吸收后掩盖问题。完整训练与解码约定见[模型架构设计](../model-architecture-v1.md#stage)；分类头、损失与解码现已实现，验证范围见[实现验收](../setup/td-vla-v1-validation.md)。

### 六任务阶段及转换语义

下表保留已讨论的任务内词表，给出事件含义；本轮事件证据阈值与确认方式见下节；它们是小样本实现参数，不是跨资产通用的冻结标准。

| 任务 | 阶段序列 | 重点定位的转换事件 |
| --- | --- | --- |
| move_stapler_pad | 0 接近抓取 → 1 持物搬运 → 2 对齐放置 → 3 完成 | 可靠抓取建立；进入目标放置区域；官方成功 |
| lift_pot | 0 接近抓取 → 1 双臂持握/抬升 → 2 完成 | 双臂建立有效持握；官方成功 |
| handover_block | 0 接近抓取 → 1 左臂持物 → 2 双臂交接 → 3 右臂持物/放置 → 4 完成 | 左臂抓取；右臂开始有效接握；交接完成；官方成功 |
| beat_block_hammer | 0 接近抓取 → 1 持锤搬运 → 2 对齐敲击 → 3 完成 | 可靠持锤；锤头进入目标区域；官方成功 |
| stack_blocks_two | 0 接近第一块 → 1 持握第一块 → 2 第一块已放置/接近第二块 → 3 持握第二块/堆叠 → 4 完成 | 第一块抓取；第一块在目标处释放并获得支撑；第二块抓取；官方成功 |
| place_object_basket | 0 接近物体 → 1 持物/放入 → 2 物体在篮中 → 3 持篮/抬升 → 4 完成 | 物体抓取；物体释放并落入篮中；转为持篮操作；官方成功 |

接触与距离阈值是定位事件的证据，不是每一帧重新分类的依据。锤击使用锤头功能点；入篮不能只因碰到篮沿就转换；
物体仍被夹持时偶然碰到篮子不代表开始持篮；放置事件需排除物体仍在下落的情况。
阶段转换边界相对人工检查的合理事件时刻，允许 1 秒以内的偏差（用户于 2026-11-14 确认）。不追求逐物理步的精确转换；阶段漏失、语义错误或顺序错误不属于时间容差。不同确认时长之间的边界差异仅用于敏感性检查，不能替代对真实事件时刻的核验。

### v4 本轮实现参数

- 默认未来 3 秒、10 点，按实际时间戳选最近帧，同距取较早帧；选中的有效帧必须晚于当前帧。记录目标时间、实际时间、原始索引，不插值。末尾超出请求仍判无效。
- 投影有效性要求有限坐标且相机深度大于 `1e-4 m`；出画不影响有效性。
- 非终止事件连续成立至少 0.12 秒才确认，约为三帧；边界回溯到该连续段首帧。官方成功首帧直接作为完成边界。
- 先独立寻找各事件的首个确认段，再检查边界严格递增、确认段不跨越下一边界；不人为把较早事件推迟来制造合法顺序。
- 持握候选为同一物体接触两指且夹爪命令小于 0.8；双臂持握须两侧均满足。瞬时单指接触不屏蔽段内标签。
- 订书机与锤头功能点接近目标采用 XY 距离小于 4 cm；第一块放置要求目标 XY 距离小于 3.5 cm、释放、高度距初始高度小于 2 cm、相邻帧速度小于 5 cm/s。
- 入篮事件采用原物体已释放、与篮接触且中心距离小于 15 cm，并经持续确认；持篮事件额外要求篮子被持握。该入篮判据仍是粗粒度近似，本轮已结合两种资产的边界图像抽查。
- 缺失事件、顺序或确认段冲突时，回合标为 `review_required`，Stage 全部为 `-1` 且 `stage_valid=False`；Track 仍生成，原始 Action 不受影响。禁止把 `-1` 当作有效类别。
- 全无有效 Track 的回合正常保存掩码，无法定义的统计值写 `null`；数据入口只应接收带完整 `manifest.json` 的版本目录，未完成目录不可用于训练。

## 4. 数据产物与验收

新版标签必须使用独立版本标识，并关联原始 episode、文件校验值、采样配置、几何定义、任务词表和转换规则版本。
每回合保留阶段边界表与简短事件依据，标签可从边界表展开；Track 的时间偏移、左右身份和有效掩码应可审计。
正式派生数据放在 `data/` 的版本目录，`logs/` 只保留必要运行摘要和分析，避免将临时诊断目录当成训练数据源。

验收重点：Track 的投影方向、左右身份、时间对应、出画与遮挡监督、末尾掩码；Stage 的阶段顺序与关键边界是否符合任务流程。
抽查边界附近连续片段即可，不以所有帧物理接触一致为目标。记录缺失事件和明显错误边界；有效比例和重跑一致性都不能替代语义检查。
本轮标签已生成，但现有 Action-only 诊断训练仍不证明辅助模态有效。

## 5. 每次任务完成后的清理

按 [工程约定](../engineering-conventions.md#任务收尾与产物清理) 执行。
临时标签、重复叠图、测试输出、无用日志和重复诊断检查点在任务结束前删除；仅保留可复现所需的最小记录。
清理不能删除原始专家数据、正式模型、必要配置与来源信息，或尚待定位问题的唯一证据。

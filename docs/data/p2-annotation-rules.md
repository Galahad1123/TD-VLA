# P2 先导标注 v3（候选规则）

本文件描述诊断用规则，不是 P3 冻结协议。先导回合只检验可行性，不能证明所有姿态、物体和恢复路径都可靠。

## 原始记录与时间

保持 bf44be5 上游 demo_clean.yml 和原版专家 play_once，包装 scene.step 在完成一次真实物理步后只读采样。
250 Hz 物理仿真，每 15 步记录一次，约 16.67 Hz；初始帧步数为 0，另存终止帧，末间隔可小于 15 步。
不修改关节命令、接触属性、随机化开关或成功函数。每条 HDF5 保存原始配置 SHA、代码提交和专家成功标记。
`qpos` 沿用上游 joint_action.vector：12 个关节 drive target 与两个归一化夹爪命令，顺序为左臂 6+夹爪、右臂 6+夹爪；它不是传感器实测关节角。
实际夹爪几何由当前物理 link pose 计算。当前驱动目标作为基线 state，与上游接口一致。

Action 标签用 t+1 至 t+50 的未来命令；Track 使用完全相同的帧索引，以当前主相机矩阵投影未来实际专家回放几何中点。
两者末尾均重复终止帧并以 temporal_valid=False 排除补齐损失；终止帧不作为 action 训练起点，但保留完成阶段监督。
这属于成功专家目标运动轨迹，不代表学习策略实际执行后的预测轨迹。

## 两指中点及投影

机器人 aloha-agilex 的 fl_link7/fl_link8 为左指，fr_link7/fr_link8 为右指。
在各自碰撞 STL 的最大局部 x 末端 5 mm 区域，取内侧面 y 边界与该区域 x/z 包围盒中心，定义固定指腹几何点；
两点变换至世界坐标再平均。局部点、网格 SHA 与来源保存到 HDF5 finger_geometry。
这是第一版可复现的两指几何定义，不宣称是精确接触中心；与 TCP 分别保存，实测距离约 3.3 cm。

使用 SAPIEN intrinsic_cv/extrinsic_cv，x 向右、y 向下、z 向前；另外用 cam2world_gl 逆变换独立核对坐标约定。
Track 存原图 u/width、v/height，不裁剪越界值。track_valid 只表示正深度、图像范围和非 padding，**不等同于可见性**。
current_occluded 用当前主相机深度作遮挡提示：表面在中点前方超过 2 cm。中点可能位于两指间空隙/被抓物体内部，
该指标不能直接视作人工确认的遮挡真值，也不参与阶段或动作输入。出画的闲置臂会自然出现大量无效投影。
模型图像直接双线性 resize 到 224×224，无裁剪；叠图使用像素中心公式 `(u+0.5)*scale-0.5`。

## 阶段判定

所有规则只用当前和过去状态；不用回合时间比例、专家函数名或未来状态。ID 是任务内编号，不跨任务共享。
`held` 要求同一物体同时接触两根手指，且该臂夹爪命令 < 0.8。仅单指接触的边界设 invalid。
切换后的首个候选帧 invalid，下一帧同标签且有效时生效；允许掉落/恢复后阶段回退。
官方成功标志优先，立即标 complete，不额外改写成功定义。

| 任务 | 非终止阶段 | 关键边界 |
| --- | --- | --- |
| move_stapler_pad | 0 接近抓取；1 持物搬运；2 对齐放置 | 持物且物体与 pad 的 XY 距离 < 4 cm 时为 2；官方姿态/松爪要求仍由成功函数负责 |
| lift_pot | 0 接近抓取；1 双侧持握抬升 | 两臂都 held 才为 1，单侧 held invalid；成功为 2 |
| handover_block | 0 接近抓取；1 左侧持物；2 双侧持物；3 右侧持物放置 | 当前官方任务始终左侧生成物块；双侧接触与右侧接管明确区分；成功为 4 |
| beat_block_hammer | 0 接近抓取；1 持锤搬运；2 对齐敲击 | 官方锤头功能点与块 XY 距离 < 4 cm 作为粗粒度接近，实际击中必须由官方功能点和接触成功确认；成功为 3 |
| stack_blocks_two | 0 第一块接近；1 第一块持握；2 第一块放置、接近第二块；3 第二块持握堆叠 | 第一块 XY 距离目标 < 3.5 cm、已释放、高度距初始支撑高度 < 2 cm，且过去一帧速度 < 5 cm/s；区分两个对象身份；成功为 4 |
| place_object_basket | 0 接近物体；1 物体持握；2 物体在篮中；3 持篮抬升 | 物体与篮接触且中心距离 < 15 cm 为候选入篮；成功为 4 |

无持握证据而物体较初始高度抬升 > 2.5 cm 的未解释状态 invalid；堆叠已放置、入篮等有明确支持关系时例外。
遮挡、瞬时接触以及粗糙入篮条件可能造成错误；必须查看每任务接触覆盖、阶段回退及拼图后再冻结规则。
先导没有真实掉落/恢复例子时，单元测试只能说明软件规则允许回退，不能宣称实际恢复路径已覆盖。

锤头局部点由固定资产 model_data0.json 的 functional_matrix[0] 与 scale 得到，坐标及资产 SHA 见 configs/pilot_geometry.json。首次以锤体原点判断未触发对齐阶段，已通过真实回放发现并修正。

独立审查后补充：堆叠与篮子任务对两个被操作对象均检查单指接触、离开支撑高度以及支持关系。
第二块只有接触第一块且高度差接近 5 cm 时，才允许无夹持的悬高状态；篮子悬高而未被双指持握时 invalid。
第一块仍在目标上方下落时不能标为已放置。相关失败场景回归测试先复现再修复。

未覆盖项：未生成逐未来点的可靠遮挡真值；current_occluded=False 不能区分出画与可见，必须另用原始投影检查范围。
当前报告中的遮挡比例为所有帧上的提示比例，并非有效可见投影中的遮挡率。P3 冻结前应补充独立 visibility mask。

篮子阶段优先级：只要物体仍由夹爪持握，就属于物体持握/放置阶段；插入时两指偶然同时碰到篮子不能提前转为持篮阶段。真实回放中发现该重叠条件后已新增回归测试修正。

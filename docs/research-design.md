# TD-VLA：研究定位与设计共识

更新日期：2026-11-13。本文保留研究范围与早期架构讨论。第一版架构现已收敛为不增加 Temporal 历史的并行多流 decoder，具体以最新的 [第一版模型架构](model-architecture-v1.md) 为准。下文 Temporal–Depth、离散表示与冻结策略等早期候选不作为第一版实施要求。

本文记录讨论形成的研究共识；工程约定见 [engineering-conventions.md](engineering-conventions.md)。区分已确认决定、研究假设和未决设计，不将候选方案视为已经验证的创新。

## 1. 研究目标

受 Moshi 的 Temporal–Depth 架构启发，研究一个持续接收观测、联合输出机器人动作、空间运动意图和任务进度的 VLA。

第一版的主要用途是让辅助信息随动作同步输出，用于空间预测、状态理解和对外表达；不要求先生成辅助信息来规划当前动作。同步指输出对应同一控制窗口，并满足该窗口的延迟预算，不要求所有 token 在同一次前向中产生。

第一版使用 RoboTwin 2.0，验证已知多任务下的控制、多流输出和任务进度识别。暂不要求识别未见任务的阶段体系。优先研究复用 TurboVLA 的感知与融合模块，保留原始策略作为对照。

## 2. 核心架构假设与贡献候选

- Temporal 模块沿真实交互时间组织观测与历史信息。
- Depth 模块在同一控制窗口内建模异构输出之间的条件依赖。
- 将较昂贵的上下文建模与窗口内输出生成分离，探索多流一致性与推理成本之间的关系。

候选贡献是适用于机器人异构输出的 Temporal–Depth 建模及其闭环验证。联合输出多种信息、多个输出头或链式概率分解本身，均不足以证明架构新颖性。

若采用自回归 Depth 顺序，其抽象形式为：

\[
p(Z_t\mid C_t)=\prod_k p(z_{t,k}\mid C_t,z_{t,<k}),
\qquad Z_t=(A_t,P_t,S_t).
\]

其中 \(C_t\) 是当前可用观测、任务指令和历史上下文；具体历史内容尚未确定。顺序因子化表达统计条件依赖，不自动证明物理因果关系。

Moshi 的 Depth 模块内部仍有生成顺序。TurboVLA 则使用连续动作头，不能通过增加两个输出头就等同于 Moshi 式离散 Temporal–Depth 模型。连续输出与离散 token 的选择是下一阶段的核心设计问题。

## 3. 已确认的输出语义

### Action：未来动作

输出未来窗口的机器人动作。预测窗口长度、动作采样频率和执行后重新观测的间隔分别配置，数值尚未确定。原始 TurboVLA 的动作表示与归一化先用于基线复现，不代表 TD 模型最终结构已确定。

### Point Track：双臂夹爪的目标投影轨迹

输出主视角摄像头中，左右夹爪两指中点在未来窗口内的二维轨迹。左右身份固定；暂时不动的手也保留对应轨迹。监督来自专家轨迹回放，作为希望实现的运动意图，而非保证实际执行会发生的结果。

可将标签抽象表示为：

\[
P_t\in\mathbb{R}^{H\times2\times2},
\qquad P_t[j,a,:]=(u,v),
\]

其中 \(H\) 是未来采样点数，第二维固定为左、右臂，最后一维为图像坐标。只包含未来采样点，不包含过去的轨迹；当前点可作为单独的可视化起点。Action 与 Track 覆盖相同未来时间范围，采样频率可以不同。

工程建议是先计算三维两指中点，再投影到主相机；这与两个二维投影点的平均值不一定相同。具体机器人 link 定义、相机坐标约定、像素或归一化坐标、遮挡与出画标记仍需核验。图像裁剪和缩放必须同步变换轨迹标签。

### Subtask：任务内当前阶段 ID

每个已知任务分别定义有序阶段，预测当前所在阶段的离散 ID，不自回归生成自然语言描述。相同编号的含义依赖任务指令；可通过任务与 ID 的映射对外显示阶段名称。

阶段持续期间允许重复标签。第一版目标是正确识别任务进度，不强制建立跨任务通用技能词表。阶段编号不是连续完成百分比，各阶段时长和难度可能不同。

任务完成需要与进入最后阶段区分，具体编码待定。共享分类输出、按任务屏蔽无效类别是候选实现，不是已定接口。评估原始预测的阶段抖动与跳转，不通过强制单调后处理掩盖识别错误。

## 4. 时间轴与闭环

每个控制窗口接收新观测，更新上下文，生成 Action、目标 Track 和当前阶段。执行一定长度的动作后再次观测和预测，相邻预测窗口允许重叠。

Action 与 Track 指向未来；Subtask 描述当前。旧 Track 是过去生成的目标预测，不能作为已发生的真实运动。历史预测、实际执行动作和新观测需明确区分。

Action → Track → Subtask 是候选顺序，尚未确认。在此顺序下，本窗口的 Track 不直接参与本窗口 Action 的生成。若未来加入提前退出，需要处理下一窗口缺失辅助历史的问题；固定顺序的前缀退出也不等于任意流组合生成。

## 5. 数据与阶段标注

当前没有带阶段标注的专家数据。计划利用仿真回放或专家执行生成标签，先验证少量任务，再扩展到多任务。

- 每个任务建立基于实际状态的阶段规则，依据距离、接触、物体状态等定义边界，避免按时间比例切段。
- 当前阶段判定使用当前及此前信息；未来专家状态用于未来 Track 标签，两者不能混淆。
- 使用稳定持续条件或状态机减少边界噪声，保留规则版本并抽查可视化结果。
- 仿真特权状态用于标注与评测，不自动输入策略；检查阶段是否能从模型可见观测和历史中识别。
- 核验已有数据是否保存足够的回放状态、相机和机器人信息；不能假定转换后的动作数据足以重建标签。

CALVIN 保留为后续平台。其标准五任务链逐个提供子任务指令，并由 oracle 判定切换，不能直接替代任务内部阶段标注。

## 6. 验证研究价值

建立共享数据、预处理和评测口径的 Action-only、独立多头和 Temporal–Depth 对照。根据最终表示补充一维 AR 等必要对照，不预先实现所有路线。

关注以下结果：

- 闭环任务成功率，以及增加辅助输出是否损害控制。
- 左右 Track 的预测误差、有效点覆盖和可视化质量。
- 阶段准确性、切换提前或延迟、阶段跳跃及抖动。
- 多流输出一致性、首次动作可用延迟、完整输出延迟、显存和计算成本。
- 参数量、训练预算和推理预算差异，避免把额外监督收益误判为架构收益。

专家轨迹上的离线 Track 误差与策略闭环实际运动的偏差分别报告：偏离专家状态后，原专家未来轨迹不一定仍是唯一正确目标。阶段识别需包含不同执行速度和停顿等检查，判断模型是否仅依赖时间规律。

控制能力保持、辅助预测有用且额外延迟可接受，即具有应用价值；是否构成架构优势仍需相对基线证明。具体指标公式和验收阈值待实验协议确定。

## 7. 未决设计与备选方向

尚未确定：连续或离散输出、tokenizer、Depth 顺序与粒度、Temporal 历史内容和缓存、预测与执行窗口、阶段完成编码、任务子集、训练冻结策略和损失权重。

备选：利用专家及次优数据，学习给定动作下实际会发生的夹爪运动。其监督语义与目标 Track 不同；次优动作不能未经筛选就成为期望动作的模仿目标。

Global Drafting、Block Diffusion、任意组合选择性生成、Future RGB 和自由文本推理均保留为后续探索，不列为第一版必做项。

# 多流并行预测 VLA：全局技术路线与研究框架

我同意你的思路。我们现在不应该过早地在 Temporal-Depth AR、Global Parallel Drafting 和 Iterative Refinement 之间做取舍。

我建议把它们视为同一个研究方向下的两条主要技术路线，而不是相互替代的方案。

它们共享一个核心思想：将机器人未来行为表示为多个具有不同语义、不同时间尺度的 Primitive Stream，然后通过并行化的方式联合预测。

两条路线的区别在于：如何生成这些 Stream。

- 路线 A：Autoregressive Multi-stream Prediction。沿时间和信息流维度进行层次化自回归预测。
- 路线 B：Global Multi-Primitive Parallel Drafting。一次性并行预测所有 Primitive，再通过交互或迭代修正保证一致性。

此外，Token Compression、Codebook、Block Diffusion 等属于可以跨路线使用的技术模块。

下面我把目前讨论整理成一份相对完整的研究框架，并补充一些我认为需要提前明确的技术问题。

# 一、全局研究目标：从 Action-centric VLA 到 Multi-stream Predictive VLA

## 1. 传统 VLA 的局限

一般 VLA 的预测形式：

$ (O_t,L,q_t)\rightarrow A_{t:t+H} $

其中：

- $O_t$：当前视觉观测。
- $L$：任务指令。
- $q_t$：机器人当前状态。
- $A_{t:t+H}$：未来 Action Chunk。

模型主要关心机器人接下来应该执行什么动作。

但是机器人操作实际上涉及多个相互关联的状态：

- 机器人应该如何运动？
- 物体和空间中的点会如何运动？
- 当前正在执行哪个 Subtask？
- 当前 Subtask 是否完成？
- 下一阶段应该执行什么？

我们希望把这些信息显式建模，而不是全部隐式压缩到 Action Chunk 中。

## 2. 统一的多流表示

第一版建议保留三个核心 Primitive：

## Multi-stream VLA 的三个核心输出

**Stream A：Action**

核心控制信息

机器人未来动作，包括末端位置、旋转、夹爪状态、关节动作等。

**Stream P：2D Point Track**

空间动态信息

物体关键点、抓取点、接触点以及它们在未来时间窗口中的运动。

**Stream S：Subtask**

任务状态信息

当前任务阶段、子任务开始与完成状态、下一步任务意图。

我们暂时不将 Future RGB 和自由形式 CoT 放入第一版的核心输出。

原因：

- Future RGB 的 Token 数量和计算成本较高，而且不一定直接提高动作质量。
- 自由形式 CoT 的监督和评价比较困难。
- 2D Point Track 与 Action 有明确的空间和运动关联。
- Subtask 与 Action 有明确的任务逻辑关联。

因此，三个 Stream 已经足以研究核心架构问题。

当然，这不意味着 Future RGB 和 CoT 被永久排除，它们可以在后续实验中作为扩展模态。

## 3. 一个重要设计：三个 Stream 不一定具有相同的时间频率

这是我们与 Moshi 的重要区别。

Moshi 的音频流天然具有统一的 12.5Hz 时间轴，但机器人中的不同信息具有不同的时间尺度。

| Stream      | 时间特征                | 建议生成方式           |
| ----------- | ----------------------- | ---------------------- |
| Action      | 高频、连续              | 每个 Action Chunk 生成 |
| Point Track | 与动作预测 Horizon 对齐 | 每个 Action Chunk 生成 |
| Subtask     | 低频、事件驱动          | 任务状态变化时生成     |

例如：

![image-20261111231609325](C:\Users\32775\AppData\Roaming\Typora\typora-user-images\image-20261111231609325.png)

这里建议采用一个统一的时间索引，但允许不同 Stream 具有不同的有效 Token 位置。

可以定义：

$ Z_t=\{A_t,P_t,S_t\} $

同时增加一个有效性 Mask：

$ M_t^k\in\{0,1\} $

其中 $M_t^k=0$ 表示该 Stream 在当前时间窗口没有新的 Token 需要生成。

这比强制所有 Stream 每个时间步都生成一个真实 Token 更合理。

还有一个细节：Subtask 不应只是简单重复同一个文本 Token。我们可以考虑使用：

- `START`：Subtask 开始。
- `UPDATE`：Subtask 状态更新。
- `DONE`：Subtask 完成。
- `HOLD`：状态持续。
- `NEXT`：下一 Subtask 开始。

这样 Subtask Stream 不仅提供语义信息，还可以成为对外的实时进度接口。

这就产生了一个非常有价值的特性：

机器人在持续生成 Action 的同时，可以实时告诉用户当前正在做什么、哪个步骤已经完成、下一步将做什么。

这可以成为我们区别于普通 VLA 的一个应用层价值。

# 二、路线 A：Temporal-Depth Autoregressive Multi-stream Prediction

这是我们最初从 Moshi 得到的想法，我认为应该完整保留。

## 1. 核心思想

普通 VLA：

$ P(A_{1:T}\mid O,L) $

我们的多流 VLA：

$ P(A_{1:T},P_{1:T},S_{1:T}\mid O,L) $

更进一步，将时间维度和 Stream 维度分解：

$ \boxed{ P(Z_{1:T}\mid O,L) = \prod_{t=1}^{T} P(Z_t\mid Z_{<t},O,L) } $

在每个时间步内部：

$ P(Z_t\mid Z_{<t}) = \prod_{k=1}^{K} P(z_{t,k}\mid Z_{<t},z_{t,<k}) $

这里：

- Temporal Transformer：负责跨时间步建模。
- Depth Transformer：负责同一时间窗口内不同 Stream 的条件依赖。

![image-20261111231704410](C:\Users\32775\AppData\Roaming\Typora\typora-user-images\image-20261111231704410.png)

## 2. 不同 Stream 的生成频率

这里有一个关键设计问题：

Action 和 Point Track 可以采用相同的时间频率，但 Subtask 不需要。

因此，我建议把 Subtask 定义为一种 Event-driven Stream。

例如：

$ S_t= \begin{cases} \text{START}(s),&\text{开始新 Subtask}\\ \text{DONE}(s),&\text{完成当前 Subtask}\\ \text{HOLD},&\text{状态不变} \end{cases} $

这样在每个 Temporal Step 中：

- Action：正常生成。
- Point Track：正常生成。
- Subtask：可以生成真实事件 Token，也可以生成 HOLD / PAD。

需要注意：如果采用 PAD 占位，训练时最好使用有效位置 Mask，避免大量 PAD Loss 淹没真正的 Subtask 监督。

## 3. AR 路线还有一个重要优势：Action-first Early Exit

这一点是你提出的、我认为非常值得保留的想法。

我们不一定需要在推理时生成全部 Stream。

假设 Depth Transformer 的生成顺序是：

$ Subtask\rightarrow Action\rightarrow PointTrack $

训练时：

$ \mathcal L= \mathcal L_S+ \mathcal L_A+ \mathcal L_P $

模型学习完整的联合预测。

推理时可以只生成：

$ Subtask\rightarrow Action $

然后直接停止。

Point Track 不需要真正生成。

这意味着：

- 训练阶段：模型利用所有监督学习更丰富的状态表示。
- 推理阶段：只生成真正需要的动作。
- 需要空间可视化或规划信息时，再继续生成 Point Track。

这里必须强调，未生成 Point Track 时，模型仍然可以通过历史上下文和训练学到的参数使用空间知识，但不能声称它已经在当前推理中获得了显式的 Point Track 预测。

## 4. AR 路线的两种生成顺序

我建议至少研究两种：

| 方案             | Depth 顺序                     | 特点                   |
| ---------------- | ------------------------------ | ---------------------- |
| A1：Action-first | Action → Point Track → Subtask | 优先快速输出可执行动作 |
| A2：Task-first   | Subtask → Action → Point Track | 更符合任务规划逻辑     |

其中 Action-first 有一个非常重要的优势：

一旦生成 Action，就可以提前终止 Depth 解码。

而 Task-first 则可以让模型先输出任务状态，再生成动作。

我们不应该现在就决定哪一个最好，应该把它们作为独立的实验分支。

另外，Depth 顺序不仅影响推理效率，还影响概率分解方式。比如 Action-first 表示：

$ P(A,P,S\mid O,L) = P(A\mid O,L) P(P\mid A,O,L) P(S\mid A,P,O,L) $

Task-first 则是另一种分解。

二者理论上可以表示相同的联合分布，但模型容量、监督难度、误差传播和 Early Exit 能力会有所不同。

# 三、路线 B：Global Multi-Primitive Parallel Drafting

这是另一条独立的技术路线。它的核心不是按照时间和 Stream 的顺序逐步生成，而是：

把未来需要预测的所有 Primitive 组织成一个整体，在同一个模型前向中并行 Draft。

我建议保留我们之前讨论的三种实现方案。

## 1. B1：Shared Global Latent + Parallel Heads

首先，从当前观察和语言指令中提取一个全局计划表示：

$ G=E_\theta(O,L,q) $

然后使用多个独立 Head：

$ \begin{aligned} \hat A&=D_A(G)\\ \hat P&=D_P(G)\\ \hat S&=D_S(G) \end{aligned} $

![image-20261111231738435](C:\Users\32775\AppData\Roaming\Typora\typora-user-images\image-20261111231738435.png)

优点：

- 实现最简单。
- 不同输出可以完全并行。
- 很容易接入 FAST、VQ、RVQ。
- 可以作为最重要的 Parallel Multi-head Baseline。

缺点：

- 三种输出只通过 Global Latent 间接关联。
- Action Head 无法直接读取当前预测的 Point Track。
- 如果不同输出需要复杂的相互约束，单一 Global Latent 可能不够。

我认为这个方案必须实现，因为它可以回答一个基础问题：

我们需要复杂的 Cross-Primitive Modeling，还是一个足够强的 Shared Latent 就已经足够？

## 2. B2：Cross-Primitive Attention

这是比 B1 更强的方案，也是我认为最值得优先尝试的 Global Drafting 架构。

我们为每种 Primitive 分配一组 Slot：

$ Z_{\mathrm{mask}} = [Z_A^{mask},Z_P^{mask},Z_S^{mask}] $

所有 Slot 一起进入一个 Transformer。

不同 Primitive 之间通过 Bidirectional Attention 交换信息。

$ H_D= T_D(H,Z_{\mathrm{mask}}) $

然后分别预测：

$ \begin{aligned} \hat Z_A&=Head_A(H_D)\\ \hat Z_P&=Head_P(H_D)\\ \hat Z_S&=Head_S(H_D) \end{aligned} $

![image-20261111231824525](C:\Users\32775\AppData\Roaming\Typora\typora-user-images\image-20261111231824525.png)

这个方案比独立 Head 更强，因为模型可以在 Hidden Space 中建立不同 Primitive 之间的关系。

但这里有一个重要的概率建模细节：

如果所有输出 Token 都是 Masked 的，那么它们可以通过 Masked Slot 的 Hidden States 相互交互，但不能直接看到其他 Primitive 的最终采样结果。

因此，B2 仍然是并行预测近似，而不是严格的联合自回归采样。

## 3. B3：Iterative Parallel Refinement

这是最有意思的方案。

第一轮，所有 Primitive 同时 Draft：

$ Z^{(1)}=D_\theta(H,Z^{mask}) $

第二轮，每个 Primitive 根据上一轮所有预测结果更新：

$ Z^{(2)}=D_\theta(H,Z^{(1)}) $

重复 R 次：

$ \boxed{ Z^{(r+1)}=D_\theta(H,Z^{(r)}) } $

这样，每一轮都并行生成所有 Primitive，但是跨 Primitive 的依赖可以逐步建立。

例如：

- 第一轮：Action 和 Point Track 各自生成粗略预测。
- 第二轮：模型发现二者不一致，调整轨迹。
- 第三轮：Action、Track 和 Subtask 达成更一致的结果。

![image-20261111231854050](C:\Users\32775\AppData\Roaming\Typora\typora-user-images\image-20261111231854050.png)

这里就需要研究 Block Diffusion、Masked Diffusion 和 Parallel Refinement。

# 四、Block Diffusion：它是路线 A 和路线 B 之间的重要桥梁（已被做过）

你提到需要调研 Block Diffusion，我已经针对这一方向做了进一步检索。

有一个重要发现：

Block Diffusion 不只是语言模型中的概念，2026 年已经有多篇工作将其用于 VLA。

而且有些工作和我们设想的 Temporal-Depth 结构非常接近。

## 1. Block Diffusion 的基本思想

2025 年 ICLR 的论文：

Block Diffusion: Interpolating Between Autoregressive and Diffusion Language Models

它的核心设计：

- Block 之间采用 Autoregressive。
- Block 内部采用 Discrete Diffusion。
- 同一个 Block 内的 Token 可以并行去噪。
- 不同 Block 之间保持因果关系。

概率分解：

$ P(X)= \prod_{b=1}^{B} P(X^{(b)}\mid X^{(<b)}) $

其中：

$ P(X^{(b)}\mid X^{(<b)}) $

通过一个离散 Diffusion 模型实现。

这个设计非常重要，因为它保留了 AR 的优势：

- 任意长度生成。
- KV Cache。
- 前面 Block 的结果可以作为后面 Block 的条件。

同时又具有 Diffusion 的优势：

- Block 内部并行生成。
- 不需要每个 Token 都执行一次串行前向。
- 可以利用双向上下文修正同一个 Block 内的预测。

## 2. 已经出现的 VLA 工作

我找到至少三篇直接相关的工作。

**BlockVLA**

2026

Accelerating Autoregressive VLA via Block Diffusion Finetuning

[arXiv:2605.13382](https://arxiv.org/abs/2605.13382?utm_source=chatgpt.com)

使用预训练 AR VLA Backbone，将 Action 序列划分为 Block。Block 内并行离散去噪，Block 间保持 AR。论文报告相较标准 Discrete Diffusion VLA 有 3.3 倍推理加速。

**TBD-VLA**

CoRL 2026

Temporal Block Diffusion Vision Language Action Model

[arXiv:2606.07895](https://arxiv.org/abs/2606.07895?utm_source=chatgpt.com)

将 Action 按时间窗口划分成 Block，Block 内并行 Masked Diffusion，Block 间自回归。还支持 Real-Time Chunking 和 Temporal Inpainting。

**Concertina**

2026-11-05

Embodying Manipulation and Cognition in One Diffusion Vision-Language Model

[arXiv:2611.07513](https://arxiv.org/abs/2611.07513?utm_source=chatgpt.com)

将连续 Action Latent 直接放进共享 Diffusion VLM，使用 Blockwise Generation，Block 内并行重建，Block 间保持因果顺序。还支持单次并行生成和风险引导的迭代 Refinement。

这三篇论文的存在意味着：

我们不能再把「Temporal Block AR + Block 内并行生成」本身作为创新。

但是它们主要处理的是 Action 序列，而不是 Action、Point Track 和 Subtask 等异构 Stream 的联合生成。

这一差别很重要。

## 3. 我们可以如何扩展 Block Diffusion？

我认为有一个很自然的扩展：

将 Block 从 Action-only Block 扩展成 Multi-Primitive Block。

传统 BlockVLA：

$ B_t=A_t $

我们的设计：

$ \boxed{ B_t=\{A_t,P_t,S_t\} } $

每个 Block 不再只有 Action Token，而是包含：

- Action Token Block。
- Point Track Token Block。
- Subtask Event Token（如果当前窗口发生事件）。

然后：

$ P(B_{1:T}\mid O,L) = \prod_{t=1}^{T} P(B_t\mid B_{<t},O,L) $

但是每个 Block 内部使用联合 Masked Diffusion：

$ P(B_t\mid B_{<t}) $

通过一个共享 Transformer 同时更新 Action、Point Track 和 Subtask 的 Masked Token。

这样就形成：

![image-20261111232103249](C:\Users\32775\AppData\Roaming\Typora\typora-user-images\image-20261111232103249.png)

这是我认为值得认真研究的第三条技术分支。

它不是简单的 Temporal-Depth AR，也不是完全独立的 Global Parallel Drafting，而是两者之间的混合方案：

- 时间维度：保持因果。
- 同一时间窗口：多流并行。
- 同一 Block 内：通过多轮 Diffusion / Refinement 建立跨流依赖。

## 4. Block Diffusion 和 Iterative Parallel Refinement 的关系

这两者非常接近，但不完全相同。

| 方法                 | 主要机制                 | 时间结构             |
| -------------------- | ------------------------ | -------------------- |
| One-shot Parallel    | 一次预测全部输出         | 无显式生成顺序       |
| Iterative Refinement | 多轮更新全部输出         | 依赖 Refinement 轮次 |
| Block Diffusion      | Block 内多轮去噪         | Block 间 AR          |
| Temporal-Depth AR    | 时间和 Stream 两轴自回归 | 两轴均有显式顺序     |

Block Diffusion 可以看作 Iterative Parallel Refinement 的一种具有明确概率建模和训练目标的实现。

而 Iterative Refinement 也不一定必须采用 Diffusion。例如，可以采用：

- Jacobi-style Parallel Update。
- Masked Token Refinement。
- Confidence-based Re-masking。
- Learned Residual Refinement。

我建议将 Block Diffusion 作为路线 B 和路线 A 的桥梁来研究，而不是把它单独看成一个无关的方向。

# 五、两条主要路线的完整对比

现在我们已经有了三种不同的生成范式：

1. Temporal-Depth Autoregression。
2. Global Multi-Primitive Parallel Drafting。
3. Multi-Primitive Block Diffusion。

我建议不要急于合并它们，而是明确各自解决的问题。

| 比较维度       | 路线 A：TD-AR            | 路线 B：Global Drafting | 路线 C：Block Diffusion     |
| -------------- | ------------------------ | ----------------------- | --------------------------- |
| 时间建模       | Temporal AR              | 可选                    | Block 间 AR                 |
| Stream 建模    | Depth AR                 | 并行 Attention          | Block 内联合去噪            |
| Primitive 生成 | 逐 Stream                | 全部并行                | 一个时间 Block 内全部并行   |
| 跨流依赖       | 显式条件概率             | Attention / Refinement  | Denoising 过程              |
| 生成次数       | 随 Token / Stream 数增加 | 一次或少数几次          | 随 Block 数及去噪步数增加   |
| KV Cache       | 容易支持                 | 取决于架构              | Block 间支持                |
| Early Exit     | 非常自然                 | 需要额外设计            | 可以跳过后续 Stream / Block |
| 时间一致性     | 自回归保证部分因果结构   | 需要 Refinement         | Block 间因果保证            |

这里需要特别注意：

路线 A 的 Temporal-Depth AR 和路线 C 的 Block Diffusion 虽然都保留了时间因果结构，但生成机制完全不同。

- TD-AR：一个时间窗口内的 Stream 依次生成。
- Block Diffusion：一个时间窗口内的 Stream 一起去噪。

两者都值得研究。

# 六、跨路线可使用的加速技术

这一部分我们可以作为独立的技术模块，不需要在一开始就决定使用哪条生成路线。

## 1. Action Token Compression：FAST / DCT / BPE

FAST: Efficient Action Tokenization for Vision-Language-Action Models

[论文](https://arxiv.org/abs/2501.09747?utm_source=chatgpt.com)

Action Chunk 先通过 DCT 转换到频域，再进行量化和 BPE 压缩。

它可以应用于：

- TD-AR：减少自回归 Token 数。
- Global Drafting：减少需要并行预测的 Slot。
- Block Diffusion：缩短每个 Action Block。

但是需要注意，FAST 的 BPE 序列具有变长、跨时间片段合并的特征，这可能不利于严格的时间位置对齐。

因此建议同时保留两种 Action Tokenizer：

| Tokenizer         | 优点             | 缺点                  |
| ----------------- | ---------------- | --------------------- |
| FAST + BPE        | 压缩率高         | 时间位置不固定        |
| DCT + Fixed VQ    | 固定长度，易并行 | 压缩率可能较低        |
| RVQ               | 表示能力较强     | 可能需要多层 Token    |
| Continuous Latent | 避免量化误差     | 不适合直接使用离散 AR |

## 2. Point Track Compression：Trajectory Codebook

Point Track 的原始表示：

$ P\in\mathbb R^{N\times H\times 2} $

可以使用一个专门的 Trajectory Tokenizer：

$ z_P=E_P(P) $

$ \hat P=D_P(\operatorname{VQ}(z_P)) $

这里我建议把一个点在未来一段时间的轨迹作为一个编码对象，而不是每个时间步、每个坐标单独量化。

例如：

- 一个 Primitive 可以包含 10～20 个查询点。
- 每个点的完整未来轨迹可以被压缩成少量 Token。
- 不同点的 Token 可以同时生成。

但需要注意，点之间的关系也很重要。例如抓取点、接触点和物体中心的运动并不独立。

因此，Trajectory Tokenizer 可以尝试两种设计：

- Point-wise VQ：每个点单独编码。
- Object-centric Joint VQ：将同一物体的多个关键点联合编码。

我更推荐先做 Object-centric Joint VQ。

## 3. Codebook Dimension Reduction

这是我们之前讨论的另一种压缩方向。

假设一个 Stream 的 Latent Dimension 为 512，可以通过：

- PCA / Learned Projection。
- Product Quantization。
- Residual Vector Quantization。
- Grouped VQ。
- Low-rank Codebook。

将表示压缩到更小的空间。

但这里有一个值得研究的区别：

Codebook 数量减少，不代表生成 Token 数量一定减少。

例如，RVQ 使用 8 层 Codebook，每个时间窗口仍然要生成 8 个 Token。它只是提高了表示的离散化能力。

真正减少解码次数需要：

- 减少每个 Primitive 的 Token 数量。
- 将多个时间点编码成一个 Token。
- 将多个 Codebook 层压缩成一个组合 Token。
- 使用并行预测代替串行预测。

因此，我们应该同时报告 Token Compression Ratio 和 Sequential Decoding Steps，而不能只报告 Codebook Size。

## 4. KV Cache + Asynchronous Execution

这两项也很重要。

- AR 路线：使用 Temporal Transformer 的 KV Cache，避免重复计算历史时间步。
- Global Drafting：缓存共享 Context，只更新输出 Slot。
- Block Diffusion：完成的历史 Block 可以缓存，后续 Block 只需要进行局部去噪。
- 所有路线：执行当前 Action Chunk 的同时，异步预测下一 Chunk。

TBD-VLA 的 Temporal Inpainting 和 Concertina 的 Blockwise Generation 都提供了非常值得借鉴的实时执行设计。

## Phase 1：先建立统一的多流数据和 Tokenizer

- A2：Subtask-first AR。

- Depth Transformer。

- Multi-rate Modeling。

路线 B：Global Parallel Drafting

建议实现：

- B1：Shared Global Latent + Parallel Heads。

- Primitive Slot Design。
- Cross-Primitive Attention。
- 一次前向和多轮 Refinement 的精度—延迟权衡。

## Phase 3：加入 Block Diffusion，形成第三条路线

在前两条路线的基础上，实现：

- C1：Action-only Block Diffusion。
- C2：Action + Point Track Joint Block Diffusion。
- C3：Action + Point Track + Subtask Multi-Primitive Block Diffusion。

这里最重要的是 C2 和 C3。

我们需要研究：

$ B_t=\{A_t,P_t,S_t\} $

如何在一个 Block 内进行联合 Masked Diffusion，以及不同模态是否需要不同的 Noise Schedule。

- FAST / DCT / BPE。
- RVQ / Product Quantization。
- KV Cache。
- Asynchronous Execution。
- Action Early Exit。

# 九、必须提前明确的几个研究问题

我认为有五个问题需要在正式实现前讨论清楚。

### 问题 1：Action 和 Point Track 谁应该先生成？

这是 AR 路线最重要的选择。

如果：

$ A\rightarrow P $

模型学习的是 Action 对未来空间运动的影响。

如果：

$ P\rightarrow A $

模型学习的是利用预测的空间运动规划动作。

前者更适合 Action-first Early Exit，后者更适合使用空间预测指导动作。

我建议两者都做消融实验。

另外，如果 Subtask 需要实时对外播报，建议采用低频 Event Head，或者将任务事件放在 Action 前面。否则 Action-first Early Exit 会导致 Subtask Stream 根本没有被解码。

### 问题 2：Global Drafting 的联合一致性如何保证？

Shared Global Latent、Cross-Primitive Attention 和 Iterative Refinement 的能力并不相同。

我建议把它们作为三个独立模型，而不是直接组合成一个复杂模型。

### 问题 3：不同 Stream 的 Tokenizer 应该独立还是共享？

我倾向于：

- Tokenizer 独立。
- Codebook 独立。
- Hidden Dimension 统一。
- Transformer 参数共享或部分共享。

因为 Action、Point Track 和 Subtask 的物理意义不同，没有必要强行共享量化空间。

### 问题 4：是否所有 Stream 都需要生成？

不需要。

这是一个非常重要的设计原则：

- 只需要控制：生成 Action。
- 需要空间规划：生成 Action + Point Track。
- 需要任务状态播报：生成 Subtask。
- 需要完整世界预测：生成全部 Primitive。

模型应该支持按需生成（On-demand Generation）。

这对实际部署非常有价值。

### 问题 5：一次前向和多轮前向究竟如何比较？

不要只比较模型调用次数，还需要比较：

- GPU FLOPs。
- KV Cache 大小。
- Peak Memory。
- End-to-end Latency。
- Action Quality。
- Closed-loop Success Rate。

特别是 B3 和 Block Diffusion，虽然前向次数较少，但每次前向可能处理更大的联合序列。

## 十二、我建议的实际研究优先级

最后，我不建议现在就选定某条路线作为最终论文架构。

我建议采用以下优先级：

| 优先级 | 研究内容                                       | 原因                         |
| ------ | ---------------------------------------------- | ---------------------------- |
| P0     | 统一 Action / Track / Subtask 数据与 Tokenizer | 所有路线的共同基础           |
| P1     | Temporal-Depth AR                              | 最初的核心架构想法，需要保留 |
| P1     | Global Multi-Primitive Drafting                | 最直接的并行生成方向         |
| P2     | Block Diffusion                                | AR 与并行生成的自然桥梁      |
| P2     | FAST / Trajectory VQ                           | 降低各路线的 Token 成本      |
| P3     | Future RGB / CoT 扩展                          | 在基础架构得到验证后再加入   |

我认为目前最重要的不是选出一个最优架构，而是建立一个能够公平比较这三种生成范式的统一实验平台。

这样即使最终 Temporal-Depth AR 不如 Global Drafting，或者 Block Diffusion 在某些任务上更优，我们也不会丢掉之前的研究思路，而是能明确知道每一种架构适合解决什么问题。

我的建议是把整个项目的核心研究问题暂时写成：

> How can heterogeneous robot primitives be represented and jointly predicted in a unified multi-stream VLA, and what are the trade-offs between autoregressive, globally parallel, and block-diffusion generation paradigms?

中文：

如何在统一的多流 VLA 中表示并联合预测异构机器人 Primitive，以及自回归、全局并行 Drafting 和 Block Diffusion 三种生成范式各自具有怎样的优势与局限？

这个问题足够完整，也能容纳我们已经讨论出的所有技术路线，而不需要现在就放弃其中任何一个。

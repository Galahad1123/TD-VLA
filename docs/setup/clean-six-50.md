# 六任务 300 条 Clean 专家数据运行说明

用户于 2026-11-14 确认每任务 50 条成功回合；沿用六任务、官方成功判定与 v4 标注，不因标签异常筛种子。
阶段边界误差允许 1 秒内；缺失阶段、顺序或语义错误不因此豁免。

## 数据与执行

远端 `data/clean-six-50/` 从原有 15 次尝试（12 成功）复制开始，原先导数据保持不变。
两张 GPU 各运行一个独立仿真进程；同一任务最多一个在途回合，从已有最大种子继续顺序尝试，达到 50 成功后停止该任务。
原始回合由 manifest 记录成功/失败、配置与 SHA256；成功回合标注放 `data/clean-six-50-labels-v4/`。
标签异常只记 review_required，不替换这条成功专家轨迹；阶段规则调整需重新生成版本，不能借调整规则改变数据选取。

```bash
cd /root/TD-VLA
source scripts/env.sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/collect_clean_subset.py \
  --data data/clean-six-50 --labels data/clean-six-50-labels-v4 \
  --logs logs/clean-six-50 --target 50 --gpus 0,1
```

生产启动以 nohup 或持久会话托管上述命令。状态见 `logs/clean-six-50/status.json`，每回合耗时见 `attempts.jsonl`，固定源码与参数见 `provenance.json`。
成功计数基于官方 expert_success，不基于进程退出码或标注有效率。单回合上限 900 秒、每任务上限 500 次尝试；意外进程错误暂停新调度，保留诊断，等待已有工作完成。
完整标签 manifest 仅在 300 条成功回合全部处理后写入。运行中出现的单回合文件不等同于整个数据版本已验收。

## 恢复与清理

同一原始数据集禁止两个批处理同时启动，锁放在数据目录，不能通过更换日志目录绕过；恢复检查源码/配置与原始 SHA256，不覆盖已有回合。
异常中断的 partial HDF5 必须先检查，不自动删除原始故障证据。派生标注先写临时目录，再原子发布；恢复时可清理并重建未发布的派生标签。
成功回合的过程日志即时删除；失败专家日志只保留紧凑末尾摘要，仿真进程异常保留完整故障日志。
任务结束保留原始数据、标签/边界依据、必要审查图、运行统计与验收报告，清理测试目录和已替代日志。

## 时间估计

双卡初测：订书机 44.798 秒、交接 57.118 秒、抬锅 47.543 秒、锤击失败回合 42.247 秒、堆叠 56.118 秒、入篮 54.853 秒，均包含进程启动、规划、采集和落盘。
按约 50–60 秒/尝试、成功率约 80%、并发度 2，剩余约 280 多条成功回合预计需要 2.5–3 小时生成；含标注和异常检查预留 3–4 小时。
这是小样本预估，更多任务/种子的规划失败率会改变实际完成时间；最终以状态和累计耗时更新，不将 ETA 当作完成承诺。
